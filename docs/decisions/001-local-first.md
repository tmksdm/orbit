# ADR-001: Local-first — без backend, аутентификации и облачной синхронизации

- Статус: принято (Accepted)
- Дата: 2026-10-07
- Стадия: Stage 0 (Project Foundation)

## Context

Orbit — приложение для поддержания социальных связей. Первая платформа — Android.
На старте продукт развивается одним разработчиком с помощью coding agents; данные
персональные и чувствительные (список людей и история общения). Возможностей
сопровождать backend и платить за инфраструктуру нет. При этом общая идея
предполагает позднее появление iOS и, возможно, синхронизации между устройствами —
архитектура не должна это исключать.

## Decision

Первая версия приложения — **local-first**: все данные хранятся локально на
устройстве (Expo SQLite), приложение полностью работает без сети, backend,
аутентификации и облачной синхронизации нет.

Архитектурное следствие: domain layer не зависит от инфраструктуры (React, Expo,
SQLite, UI), доступ к данным — через интерфейсы (порты), объявленные в domain, с
реализацией в `src/data` (см. `ARCHITECTURE.md`). Это позволяет позже добавить
синхронизацию, не переписывая domain layer.

## Consequences

Положительные:

- нет затрат и операционной сложности собственного backend'а;
- данные пользователя не покидают устройство — приватность по умолчанию;
- приложение работает офлайн; запуск и проверка идей быстрее;
- меньше поверхность атак и регуляторных обязательств.

Отрицательные / риски:

- смена или потеря устройства означает потерю данных, пока не появятся экспорт или
  синхронизация;
- синхронизация между устройствами в первой версии недоступна;
- позднее добавление sync потребует решить вопрос конфликт-мержа — смягчается
  изоляцией domain и портами в data.

Аутентификация и cloud sync сознательно НЕ входят в Stage 0 и ближайшие планы;
пересмотр решения — отдельным ADR.
