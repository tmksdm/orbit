# DOMAIN.md — доменные концепции и правила изменения интервала

Документ фиксирует понятия будущего domain layer и продуктовые правила поведения
алгоритма настолько точно, чтобы на Stage 1 их нельзя было произвольно
переинтерпретировать. На Stage 0 алгоритм НЕ реализован — здесь только словарь,
правила и предварительные ориентиры. Техническая реализация — Stage 1
(см. `docs/plans/stage-1-domain.md`).

Источник истины для правил ниже — уточнение продукта от 2026-10-07
(`stage-0-domain-clarification`). Если другой документ противоречит этому
уточнению — правится тот документ, а не правила здесь.

## Понятия

| Понятие | Смысл |
|---|---|
| **Contact** | Человек в «орбите» пользователя: имя, заметка, contact strategy, границы интервалов, история взаимодействий. |
| **Interaction** | Факт общения: когда состоялся, initiator, outcome. |
| **Contact strategy** | Стратегия связи для контакта: `maintain` или `grow`. |
| **maintain** | Стратегия «не потерять»: интервалы постепенно увеличиваются при пользовательской инициативе и не сокращаются — сама по себе эта стратегия не сближает. |
| **grow** | Стратегия «сближаться»: интервал может сокращаться, но только при положительных сигналах взаимности. |
| **Initiator** | Кто инициировал взаимодействие: `me`, `them` или `mutual`. |
| **Outcome** | Результат взаимодействия: `good`, `short` или `no_reply`. |
| **Adaptive interval** | Рекомендуемый интервал до следующего контакта; пересчитывается на основе истории взаимодействий и стратегии. |
| **Min/max interval** | Границы adaptive interval: связь не «гаснет» слишком быстро и контакт не превращается в спам. |

## Contact strategy

```ts
type ContactStrategy = "maintain" | "grow";
```

### maintain — «не потерять, не навязываться»

- Цель — не потерять контакт, но и не быть навязчивым.
- Если инициатива в основном исходит от пользователя, интервалы между
  рекомендуемыми контактами постепенно увеличиваются.
- Если другой человек сам инициирует контакт, это сигнал взаимности — интервал
  не обязан увеличиваться.
- Однако `maintain` сам по себе никогда не сокращает интервалы ради сближения.

### grow — «сближаться только вслед за взаимностью»

- Цель — постепенно увеличивать частоту общения, но только при наличии
  положительных сигналов взаимности.
- `grow` НЕ означает «писать человеку чаще независимо от его поведения».
- Сокращение интервала допускается только при положительной инициативе или
  взаимности со стороны другого человека.
- Само желание пользователя сблизиться сигналом взаимности не считается.

## Interaction

Каждое взаимодействие в будущем содержит минимум:

```ts
type Initiator = "me" | "them" | "mutual";
type Outcome = "good" | "short" | "no_reply";
```

- `good` — полноценный хороший контакт;
- `short` — короткий, поверхностный контакт;
- `no_reply` — пользователь инициировал контакт, но ответа не получил.

## Базовая логика изменения интервала

На Stage 1 формула будет оформлена технически, но её поведение должно
соответствовать правилам ниже. Множители — предварительные ориентиры из
уточнения продукта; финальные значения согласуются на Stage 1 (см. «Открытые
вопросы»).

1. **`maintain` + пользователь инициировал** — интервал постепенно увеличивается
   (ориентир: `good → × 1.4`). Цель — сохранять связь, постепенно снижая частоту
   собственной инициативы, если другой человек не проявляет своей.
2. **`maintain` + другой человек инициировал** — интервал не увеличивается только
   потому, что прошло определённое количество дней; сохраняем примерно текущий
   ритм (ориентир: `them, good → × 1.0`).
3. **`grow` + пользователь инициировал** — желание сблизиться само по себе — не
   основание писать чаще; применяется обычная логика поддержания дистанции
   (ориентиры: `good → × 1.4`, `short → × 1.7`, `no_reply → × 2.2`).
4. **`grow` + другой человек инициировал + `good`** — положительный сигнал
   взаимности, интервал может быть уменьшен (ориентир: `× 0.8`; пример: ритм
   10 дней → 8 → ≈ 6 — сближение постепенно и только вслед за реальными
   сигналами взаимности).
5. **`grow` + другой человек инициировал + `short`** — короткий контакт —
   недостаточное основание для активного сближения; интервал не сокращать
   (ориентир: `× 1.0`).
6. **`no_reply`** — `× 2.2` (или другое согласованное значение > 1). Правило
   имеет приоритет над стратегией `grow`: даже человека, с которым пользователь
   хочет сблизиться, нельзя рекомендовать преследовать всё чаще после отсутствия
   ответа.

## Границы интервала

```text
minIntervalDays = 2
maxIntervalDays = 45
```

(предварительные значения). Ни `maintain`, ни `grow` не должны уменьшать
интервал ниже `minIntervalDays` или увеличивать его выше `maxIntervalDays`.

## Ключевой инвариант

Алгоритм должен реагировать не на желание пользователя само по себе, а на
сочетание:

- стратегии пользователя;
- того, кто инициировал контакт;
- качества/результата взаимодействия;
- предыдущего ритма общения.

`grow` разрешает ускорять сближение, но не создаёт взаимность там, где её нет.

## Открытые вопросы (решить до реализации на Stage 1)

1. Точная обработка `mutual` — финально согласовать до реализации Stage 1.
2. `maintain + them + short`: «сохранить или слегка увеличить» — выбрать одно
   значение (например, `× 1.0` или лёгкий рост) — TBD.
3. `maintain + me + short`: в уточнении задано только направление («увеличить
   сильнее»), без множителя — подтвердить значение на Stage 1.
4. Накопление: как последовательность однотипных взаимодействий меняет интервал
   (например, повторный `no_reply` — каждый раз `× 2.2` до `max`?).
5. Финальные значения всех множителей (сейчас — предварительные ориентиры).

## Принцип взаимности

> **`grow` означает сокращение интервала только при наличии положительных сигналов
> взаимности. Входящий контакт сам по себе не обязан автоматически уменьшать интервал.**

Точная математика пересчёта adaptive interval будет реализована на Stage 1;
изменения правил этого документа обязаны сопровождаться обновлением документа
(`AGENTS.md`, правило 4).

## Границы домена

Domain не знает про UI, Expo, SQLite, уведомления и сеть: он принимает факты
(взаимодействия) и выдаёт рекомендации. Отображение, хранение и напоминания —
задача остальных слоёв (`ARCHITECTURE.md`).
