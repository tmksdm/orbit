# DOMAIN.md — доменные концепции и правила изменения интервала

Документ фиксирует понятия domain layer и утверждённые продуктовые правила
пересчёта рекомендуемого интервала. Решения владельца от 2026-10-08 (финальные
множители MVP, отказ от верхней границы, база пересчёта) зафиксированы здесь и
реализованы на Stage 1 в `src/domain` (чистые функции, без React / Expo / SQLite / UI).

Если другой документ противоречит правилам здесь — правится тот документ.

## Понятия

| Понятие | Смысл |
|---|---|
| **Contact** | Человек в «орбите» пользователя: имя, заметка, contact strategy, min interval, текущий рекомендуемый интервал, история взаимодействий. |
| **Interaction** | Факт общения: когда состоялся, initiator, outcome. |
| **Contact strategy** | Стратегия связи для контакта: `maintain` или `grow`. |
| **maintain** | Стратегия «не потерять, не навязываться»: интервалы растут при пользовательской инициативе и никогда не сокращаются ради сближения. |
| **grow** | Стратегия «сближаться вслед за взаимностью»: интервал сокращается только при положительных сигналах со стороны другого человека. |
| **Initiator** | Кто инициировал взаимодействие: `me`, `them` или `mutual`. |
| **Outcome** | Результат взаимодействия: `good`, `short` или `no_reply`. |
| **Adaptive interval** | Текущий рекомендуемый интервал до следующего контакта; база для каждого следующего пересчёта. |
| **Min interval** | Нижняя граница рекомендуемого интервала (2 дня по умолчанию). Верхней границы НЕТ — см. «Верхней границы нет». |

## Типы домена

```ts
type ContactStrategy = "maintain" | "grow";
type Initiator = "me" | "them" | "mutual";
type Outcome = "good" | "short" | "no_reply";

interface Interaction {
  initiator: Initiator;
  outcome: Outcome;
  occurredAt: string; // ISO 8601
}
```

## Смысл стратегий

### maintain — «не потерять, не навязываться»

- Цель — не потерять контакт, но и не быть навязчивым.
- Если инициатива в основном идёт от пользователя, рекомендуемый интервал
  постепенно увеличивается.
- Если другой человек сам проявляет инициативу, интервал можно сохранить
  примерно прежним.
- `maintain` **никогда** не сокращает интервал ради активного сближения.

### grow — «сближаться вслед за взаимностью»

- Цель — постепенно сближаться, только при наличии положительных сигналов
  взаимности со стороны другого человека.
- Само желание пользователя сблизиться **не** является основанием уменьшать
  интервал: `grow + me` не сокращает интервал только потому, что стратегия — `grow`.
- `grow + them + good` и `grow + mutual + good` — можно сокращать.
- `grow + them + short` — не сокращаем.

Главный принцип: **`grow` позволяет ускорять сближение вслед за взаимностью,
но не создаёт взаимность там, где её нет.**

## К чему применяется множитель (критически важно)

Множитель применяется к **текущему рекомендуемому интервалу контакта**,
а НЕ к фактическому промежутку между двумя последними взаимодействиями.

```text
current recommended interval = 10 дней
strategy = grow
interaction = them + good
10 × 0.8 = 8 дней
```

Даже если человек сам написал через 2 дня после прошлого контакта, новый
интервал НЕ рассчитывается как `2 × 0.8`. Фактическая история взаимодействий —
информация о событиях, но не новая база интервала.

## Утверждённые множители MVP

| Strategy | Initiator | Outcome | Множитель |
|---|---|---|---|
| maintain | me | good | 1.4 |
| maintain | me | short | 1.7 |
| maintain | me | no_reply | 2.2 |
| maintain | them | good | 1.0 |
| maintain | them | short | 1.0 |
| grow | me | good | 1.4 |
| grow | me | short | 1.7 |
| grow | me | no_reply | 2.2 |
| grow | them | good | 0.8 |
| grow | them | short | 1.0 |
| grow | mutual | good | 0.8 |

Производные ячейки (не противоречат утверждённым правилам):

- `maintain + mutual` — как `maintain + them` (×1.0 для good/short): maintain
  никогда не сокращает интервал; взаимность лишь не даёт ему расти.
- `grow + mutual + short` — ×1.0: короткий контакт — недостаточное основание
  для сближения.
- `no_reply` — ×2.2 при любом initiator и обеих стратегиях: правило `no_reply`
  имеет приоритет.

## Повторный no_reply

Каждый новый `no_reply` снова увеличивает **текущий** рекомендуемый интервал
(`current × 2.2`). Это намеренное поведение продукта:

```text
10 дней → no_reply → 22 → no_reply → 48 → no_reply → 106 → и так далее
```

## Верхней границы нет

`maxIntervalDays` **удалён из продуктовой модели и алгоритма** — интервал может
расти без искусственного потолка. Если из-за отсутствия взаимности следующий
рекомендуемый контакт окажется через несколько месяцев, год или позже — это
допустимый результат. Приложение не удерживает искусственно человека в орбите
пользователя: если связь угасает из-за отсутствия взаимности — это нормально.

## Нижняя граница

`minIntervalDays = 2` (по умолчанию, настраивается на контакте). Нужна только
чтобы алгоритм сближения не уменьшал интервал до чрезмерно частого общения.
Результат пересчёта никогда не меньше `minIntervalDays`.

## Округление и первый интервал

- Дробные дни округляются до целого (`Math.round`): примеры из утверждений —
  `22 × 2.2 = 48.4 → 48`, `105.6 → 106`, `8 × 0.8 = 6.4 ≈ 6`.
- Новому контакту без истории задаётся стартовый интервал
  `INITIAL_INTERVAL_DAYS = 7` (дефолт реализации; значение — в открытых вопросах
  отчёта Stage 1).

## Ключевой инвариант

Алгоритм реагирует не на желание пользователя само по себе, а на сочетание:
стратегии, того, кто инициировал, результата взаимодействия и текущего
рекомендуемого ритма. `grow` разрешает ускорять сближение, но не создаёт
взаимность там, где её нет.

## Реализация

Чистые функции: `src/domain/scheduling.ts` (множители, пересчёт) и
`src/domain/contact.ts` (Contact, фабрика, применение взаимодействия).
Изменение правил = изменение этого документа и таблицы множителей в одном
коммите (`AGENTS.md`, правило 4).

## Границы домена

Domain не знает про UI, Expo, SQLite, уведомления и сеть: он принимает факты
(взаимодействия) и выдаёт рекомендации. Отображение, хранение и напоминания —
задача остальных слоёв (`ARCHITECTURE.md`).
