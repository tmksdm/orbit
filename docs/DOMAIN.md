# DOMAIN.md — доменные концепции

Документ фиксирует понятия будущего domain layer. На Stage 0 алгоритм НЕ реализован —
только словарь и принципы. Точная математика будет определена и реализована на Stage 1
(см. `docs/plans/stage-1-domain.md`).

## Понятия

| Понятие | Смысл |
|---|---|
| **Contact** | Человек в «орбите» пользователя: имя, заметка, contact strategy, границы интервалов, история взаимодействий. |
| **Interaction** | Факт общения: когда состоялся, initiator, outcome. |
| **Contact strategy** | Стратегия связи для контакта: `maintain` или `grow`. |
| **maintain** | Стратегия «не потерять»: при отсутствии инициативы с другой стороны рекомендуемые интервалы постепенно увеличиваются. |
| **grow** | Стратегия «сближаться»: интервал может сокращаться, но только при положительных сигналах взаимности. |
| **Initiator** | Кто инициировал взаимодействие: пользователь или другой человек. |
| **Outcome** | Результат взаимодействия (например: позитивный, нейтральный, без ответа). |
| **Adaptive interval** | Рекомендуемый интервал до следующего контакта; пересчитывается на основе истории взаимодействий и стратегии. |
| **Min/max interval** | Границы adaptive interval: связь не «гаснет» слишком быстро и контакт не превращается в спам. |

## Принцип стратегии `grow`

> **`grow` означает сокращение интервала только при наличии положительных сигналов
> взаимности. Входящий контакт сам по себе не обязан автоматически уменьшать интервал.**

Иллюстрации (не спецификация):

- Пользователь инициировал, человек ответил хорошо — сигнал взаимности: интервал может
  сократиться (только в рамках `grow` и в пределах min interval).
- Человек просто ответил, но встречной инициативы нет — этого недостаточно, чтобы
  сокращать интервал.
- Взаимности нет — интервал не сокращается: `grow` не форсирует общение.

Точная математика пересчёта adaptive interval (для обеих стратегий) будет определена
и реализована на Stage 1; изменения этих правил обязаны сопровождаться обновлением
этого документа (`AGENTS.md`, правило 4).

## Границы домена

Domain не знает про UI, Expo, SQLite, уведомления и сеть: он принимает факты
(взаимодействия) и выдаёт рекомендации. Отображение, хранение и напоминания —
задача остальных слоёв (`ARCHITECTURE.md`).
