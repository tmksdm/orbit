пошаговую инструкцию по установке и полный чек-лист §12 плана

> отдельного утверждения владельца** (план §12, §15).

## 1. Требования к сборке (нужны один раз)

- **Аккаунт Expo** (бесплатный) — регистрация: https://expo.dev/signup.
  EAS Build выполняет сборку в облаке; локальный Android SDK/Android Studio
  **не нужен**.
- **`eas-cli`**: `npm install --global eas-cli` (или использовать `npx eas-cli@latest`).
- **Сеть**: сборка идёт в облаке Expo, VPN не требуется.

> Почему development build, а не Expo Go (план §8.8, §12): канал уведомлений,
> поведение разрешений Android 13+, поведение после перезагрузки и Doze проверяются
> **только** в нативной сборке. Expo Go годится лишь для базового быстрого прогона.

---

## 2. Как получить сборку (одноразовая настройка + запуск)

Выполняется на вашем компьютере. Первый запуск `eas build:configure`/`eas login`
интерактивный (запросит вход в Expo).

```bash
# 1) Установить EAS CLI (если ещё не установлен)
npm install --global eas-cli

# 2) Войти в аккаунт Expo
eas login
eas whoami          # должно показать ваш логин

# 3) В корне проекта Orbit: собрать development-APK
eas build --platform android --profile development
```

Ход сборки: EAS спросит про **Android keystore** — выберите
**`Generate new keystore`** (EAS сам создаст и сохранит ключ; никаких ручных действий
не требуется). Первая сборка занимает ориентировочно 10–20 минут; далее быстрее.

По завершении `eas build` выведет **ссылку на страницу сборки** вида
`https://expo.dev/accounts/<аккаунт>/projects/orbit/builds/<id>` и QR-код. Ту же
сборку можно открыть позже:

```bash
eas build:list        # список сборок; нужна самая свежая со статусом FINISHED
```

Успех = статус сборки **`FINISHED`**. Если сборка упала — пришлите агенту ссылку на
страницу сборки (по ней виден лог); исправление — отдельными коммитами, без изменения
утверждённых алгоритмов.

## 3. Как установить APK на телефон

Откройте ссылку на страницу сборки **на самом Android-телефоне** (или отсканируйте
QR-код с экрана) и нажмите **`Install`**. Первый запуск установки:

1. Телефон покажет, что установка из этого источника требует разрешения →
   **разрешите установку из этого источника** (кнопка «Настройки» → включить
   «Разрешить из этого источника»). Это разовое действие.
2. Нажмите **`Install`** ещё раз → приложение **Orbit** появится на главном экране.

Альтернатива (через USB): файл APK можно скачать на компьютер и установить
`adb install <путь-к-файлу>.apk` при включённой USB-отладке. Для этого варианта нужен
`adb` (входит в Android SDK).

---

## 4. Как запустить приложение и подключить development-сервер

Development build — это «свой Expo Go»: приложение запускается на телефоне, а код
берётся с вашего компьютера.

1. На компьютере в корне проекта запустите dev-сервер:
   ```bash
   npx expo start
   ```
2. На телефоне откройте приложение **Orbit** (иконка на главном экране).
   - Если код и сервер в **одной Wi-Fi сети**, приложение обычно подключается сразу.
   - Если сети разные или соединение не устанавливается — включите **туннель**:
     остановите сервер (Ctrl+C) и запустите `npx expo start --tunnel`, затем снова
     откройте приложение. Либо отсканируйте QR-код из терминала через приложение.
3. Появится **launcher-экран** development build; выберите сервер/нажмите на него.
   Приложение загрузит JS с компьютера и покажет экран Orbit («Пора связаться»).

> Важно: **пока вы проходите сценарии ожидания (пункты требующие реального времени и
> перезагрузки телефона), dev-сервер можно выключить** — сборка уже содержит код и
> напоминания планируются на устройстве. Dev-сервер нужен, чтобы перезапускать
> приложение для быстрой проверки UI-сценариев.

## 5. Как фиксировать результат

Для каждого пункта ниже заведите строку в `REVIEW_REPORT.md` (раздел
«Фаза 5 — Android-тестирование»), отмечая один из статусов:

- **PASS** — сценарий выполнен, результат совпал с ожидаемым;
- **FAIL** — результат не совпал (опишите фактическое поведение — агент подготовит
  минимальное исправление отдельными коммитами);
- **NOT TESTED** — проверить сейчас нельзя (укажите причину).

Полезно приложить: версию Android, модель устройства, скриншот проблемного места.

## 6. Рекомендуемый порядок проверок

Порядок составлен так, чтобы **минимизировать повторные установки, сбросы разрешений
и длительное ожидание**: сначала быстрые UI-сценарии (без ожидания), затем сценарии,
требующие реального времени или перезапуска телефона, и в самом конце — проверки,
которые сбрасывают разрешения или требуют эмуляции ошибок.

| Группа | Пункты §12 | Нужно ожидание / действия |
|---|---|---|
| **A. Быстрые (сразу)** | 1, 2, 3, 9, 10, 13, 14 | только установка и взаимодействие с UI |
| **B. Зависит от данных due (сразу, но нужен контакт с нужным сроком)** | 4, 5, 6, 7, 8, 11, 12 | создать/подготовить контакты заранее (см. §7) |
| **C. Системные (перезагрузка/зона)** | 15, 16 | перезагрузка устройства; смена часового пояса |
| **D. Разрешения (сброс разрешений)** | 17 | отзыв/выдача разрешения в настройках Android |
| **E. Длительное ожидание (дни)** | 18 | не открывать приложение несколько дней |
| **F. Ограничение платформы** | 19 | force-stop приложения |
| **G. Эмуляция ошибки** | 20 | временное вмешательство (см. примечание к п.20) |

Практический совет: группы **A → B → C → D** проходятся в один день; **E** (п.18) и
**F** (п.19) — отдельно, с ожиданием. Не сокращайте обязательные проверки и не
подменяйте фактические результаты автоматическими тестами.

## 7. Подготовка тестовых данных (до начала сценариев)

Чтобы проверить anchor и цикл (§10.2 плана), заранее создайте контакты с разными
сроками (срок = последнее взаимодействие либо дата создания + интервал):

- **контакт с просроченным сроком** — например, создайте контакт, зафиксируйте
  взаимодействие (`no_reply`, интервал вырастет), и дождитесь наступления срока;
- **контакт с будущим сроком** — создайте контакт сегодня (срок наступит через
  интервал, старт = 2 дня);
- при необходимости — **пустой список** (для проверки anchor = null).

> Точное воспроизведение «просрочено / не просрочено» удобнее проверять, изменяя
> **время напоминания** относительно текущего времени телефона (пункт 14) — но не
> меняя даты на самом устройстве, чтобы не искажать календарные проверки.

## 8. Полный чек-лист §12 (20 пунктов)

Формат: **что сделать** → **ожидаемый результат** → **как зафиксировать**. Метки:
`[сразу]` — можно проверить немедленно; `[время]` — требует ожидания реального
времени; `[reboot]` — перезагрузка; `[разрешения]` — сброс разрешений.

---

**1. Установка development build.** `[сразу]`
- *Сделать:* собрать (`eas build --platform android --profile development`) и
  установить APK на телефон (§2–§3).
- *Ожидается:* приложение **Orbit** установлено, запускается, показывает экран
  «Пора связаться».
- *Фиксация:* PASS/FAIL; при FAIL — ссылка на лог сборки.

**2. Разрешение при первом включении.** `[сразу]` `[разрешения]`
- *Сделать:* откройте настройки напоминаний (иконка в шапке главного экрана) →
  включите переключатель «Напоминания».
- *Ожидается:* появляется **системный запрос разрешения Android** на уведомления;
  после «Разрешить» переключатель остаётся включённым.
- *Фиксация:* PASS/FAIL.

**3. Отказ в разрешении.** `[сразу]` `[разрешения]`
- *Сделать:* при следующем включении (предварительно сбросив разрешение) нажмите
  **«Запретить»**.
- *Ожидается:* напоминания **выключены**; при повторном открытии настроек показано
  понятное сообщение; если запрос больше невозможен — есть кнопка **«Открыть
  настройки Android»**.
- *Фиксация:* PASS/FAIL; отметьте, показалась ли кнопка (зависит от `canAskAgain`).

**4. Просрочено + время ещё не прошло → сегодня.** `[время]`
- *Сделать:* подготовьте просроченный контакт (§7); время напоминания поставьте позже
  текущего времени; включите «Напоминания».
- *Ожидается:* **anchor = сегодня**; уведомление приходит **сегодня** (или с
  допустимой задержкой — см. п.19-примечание/Q1).
- *Фиксация:* PASS/FAIL; время прихода уведомления.

**5. Просрочено + время уже прошло → завтра.** `[время]`
- *Сделать:* просроченный контакт; время напоминания поставьте раньше текущего;
  включите.
- *Ожидается:* **anchor = завтра**; сегодня уведомления нет; уведомление на следующий
  день. Проверьте сохранение anchor (в UI нет отдельного счётчика — фиксируйте по
  факту прихода на завтра/цикл).
- *Фиксация:* PASS/FAIL.

**6. Просроченных нет, есть будущая due → первый день цикла.** `[время]`
- *Сделать:* контакт с будущим сроком; просроченных нет; включите.
- *Ожидается:* anchor = ближайшая будущая дата due; уведомление приходит в первый день
  цикла **без** дополнительного открытия приложения.
- *Фиксация:* PASS/FAIL; проверьте, что не требуется открывать приложение.

**7. Цикл — шаг 3 календарных дня.** `[время]`
- *Сделать:* оставьте приложение напоминать; не открывайте его; следите за
  уведомлениями.
- *Ожидается:* уведомления приходят с шагом **ровно 3 календарных дня** от anchor.
- *Фиксация:* PASS/FAIL; даты прихода.

**8. День цикла без просроченных.** `[время]`
- *Сделать:* обеспечьте, чтобы в день цикла просроченных не было (закройте сроки
  заранее).
- *Ожидается:* уведомление **не** приходит; **цикл не сбивается** (следующий день
  цикла — по-прежнему через 3 дня).
- *Фиксация:* PASS/FAIL.

**9. Нажатие на уведомление.** `[сразу]`
- *Сделать:* дождитесь уведомления, нажмите на него.
- *Ожидается:* открывается главный экран, раздел **«Пора связаться»** актуален
  (показывает просроченные контакты).
- *Фиксация:* PASS/FAIL.

**10. Открытие/нажатие НЕ меняют интервалы и историю.** `[сразу]`
- *Сделать:* до и после открытия приложения / нажатия уведомления сравните список
  контактов, интервалы и историю взаимодействий.
- *Ожидается:* интервалы и история **не изменяются** (никаких новых взаимодействий).
- *Фиксация:* PASS/FAIL.

**11. Взаимодействие, убравшее последнюю просрочку.** `[сразу]` (если есть
запланированные будущие) `[время]` (если нужно дождаться показанного уведомления)
- *Сделать:* зафиксируйте взаимодействие, устраняющее последнюю просрочку.
- *Ожидается:* неактуальные **будущие** уведомления отменены; показанное неактуальное
  уведомление **исчезает** (автоматически удаляется при согласовании).
- *Фиксация:* PASS/FAIL.

**12. Взаимодействие при наличии других просрочек.** `[сразу]`
- *Сделать:* при нескольких просрочках зафиксируйте одно взаимодействие (count
  уменьшается, но просрочки остаются).
- *Ожидается:* устаревшая **показанная сводка удаляется** (её count больше не
  соответствует текущему); цикл сохраняется.
- *Фиксация:* PASS/FAIL.

**13. Отключение и повторное включение.** `[сразу]`
- *Сделать:* выключите «Напоминания», затем включите снова.
- *Ожидается:* при выключении будущие отменяются, показанное исчезает; при повторном
  включении — **прежний anchor/цикл**, пропущенные дни не догоняются.
- *Фиксация:* PASS/FAIL.

**14. Изменение времени напоминания.** `[сразу]`
- *Сделать:* измените время напоминания.
- *Ожидается:* **anchor не сброшен**; если новое время сегодня уже прошло — сегодня
  уведомления нет; расписание пересчитано под новое время.
- *Фиксация:* PASS/FAIL.

**15. Смена часового пояса.** `[сразу]` (после смены зоны)
- *Сделать:* измените часовой пояс устройства; откройте приложение.
- *Ожидается:* время **локальное**; даты цикла сохранены (пересчёт при открытии).
  Учтите: уже поставленный момент при закрытом приложении ОС не переписывает —
  допустим сдвиг до следующего открытия (план §11.3).
- *Фиксация:* PASS/FAIL + примечание.

**16. Перезагрузка телефона.** `[reboot]`
- *Сделать:* убедитесь, что есть запланированное будущее уведомление; перезагрузите
  телефон; не открывая Orbit дождитесь срока.
- *Ожидается:* запланированное уведомление по-прежнему приходит.
- *Фиксация:* PASS/FAIL.

**17. Отзыв разрешения при включённых напоминаниях.** `[разрешения]`
- *Сделать:* в настройках Android отзовите разрешение на уведомления; откройте Orbit.
  Затем выдайте разрешение снова; откройте Orbit.
- *Ожидается:* при отзыве — предупреждение в UI, **anchor сохранён**, «наши»
  уведомления сняты; при повторной выдаче — **расписание восстанавливается** с прежним
  anchor.
- *Фиксация:* PASS/FAIL.

**18. Автономность (дни без открытия приложения).** `[время]`
- *Сделать:* не открывайте приложение несколько дней (включая день цикла).
- *Ожидается:* уведомления приходят по расписанию; расписание **не ограничено коротким
  горизонтом** (план §8.11, вариант A; горизонт 366 дней).
- *Фиксация:* PASS/FAIL; даты прихода. (Полную 366-дневную автономность за один тест
  проверить нельзя — фиксируйте наблюдение за доступный период; долгосрочный горизонт
  проверен unit-тестами границы.)

**19. Force-stop — ожидаемое ограничение платформы.** `[сразу]`
- *Сделать:* полностью остановите приложение (в системном меню — «Остановить»), не
  открывая дождитесь срока.
- *Ожидается:* уведомления **не** приходят до ручного запуска приложения; после запуска
  возобновляются. Это **ожидаемое** ограничение Android, а не дефект (план §11.4).
- *Фиксация:* PASS (поведение как ожидается) / FAIL.

**20. Ошибка sync не влияет на сохранение данных.** `[сразу]`
- *Сделать:* смоделируйте ошибку синхронизации (например, временно отзовите разрешение
  или используйте временный сбой сети/планировщика так, чтобы sync вернул `ok:false`).
  Затем посмотрите на экран настроек и на данные.
- *Ожидается:* настройки **сохраняются** (не откатываются, без дублей); показывается
  ненавязчивое предупреждение **«Настройки сохранены, но обновить расписание
  напоминаний не удалось. Повторим позже.»**; при следующем запуске/возврате sync
  повторяется и восстанавливает расписание.
- *Фиксация:* PASS/FAIL + описание способа эмуляции. Если смоделировать сейчас нельзя —
  **NOT TESTED** с объяснением.
