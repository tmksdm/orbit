# Stage 4, Фаза 5 — минимальная ручная проверка на Android (preview APK)

> Объём пересмотрен по решению владельца (2026-10-10): прежний чек-лист из 20 ручных
> сценариев чрезмерен для pet-проекта. Ниже — **минимальный** набор действий владельца;
> максимум закрывается автотестами, платформенные проверки вынесены как **DEFERRED /
> NOT TESTED** с явно принятым риском. **Фактические результаты заносятся в
> `REVIEW_REPORT.md` только после реального прохождения.** Stage 4 не объявляется
> завершённым без вашего решения.

## 1. Четыре обязательных ручных действия (весь ручной объём)

1. **Установить и запустить сборку.** Приложение ставится и открывается (экран «Пора
   связаться»).
2. **Включить «Напоминания» и разрешить уведомления.** Настройки (иконка в шапке
   главного экрана) → включить «Напоминания» → системный запрос → «Разрешить».
3. **Получить одно реальное уведомление** о просроченном контакте (см. §4 — с
   тестовым контактом это происходит в день установки).
4. **Нажать на уведомление.** Открывается главный экран, раздел «Пора связаться»
   актуален.

Пункты 1, 2, 4 — сразу; пункт 3 — в назначенное время в день установки (см. §4).

## 2. Как получить сборку

Используется профиль **`preview-seeded`** (в `eas.json`): release-APK со **встроенным
JS-бандлом** — приложение работает **без dev-сервера**, только с телефона. Этот профиль
дополнительно создаёт **один просроченный тестовый контакт** (см. §4), чтобы уведомление
пришло в тот же день.

```bash
# один раз:
npm install --global eas-cli
eas login                 # войти в свой аккаунт Expo (expo.dev)

# в корне проекта Orbit:
eas build --platform android --profile preview-seeded
```

- Про **Android keystore** EAS спросит — выберите **`Generate new keystore`**.
- Первая сборка — ориентировочно 10–20 минут; в конце EAS выведет **ссылку** и QR-код.
- Успех = статус сборки **`FINISHED`** (посмотреть позже: `eas build:list`).

Обычный профиль `preview` (без тестовых данных) оставлен как есть — для чистого smoke
без фикстуры; для быстрой проверки уведомления используйте именно `preview-seeded`.

### Установка
Откройте ссылку сборки **на телефоне** → `Install` → при первом разе разрешите
установку из этого источника → `Install` ещё раз. Иконка **Orbit** появится на
главном экране. Запуск — обычным нажатием, **без** компьютера и dev-сервера.

> **Сборку может выполнить только владелец** под своим аккаунтом Expo: в песочнице
> агента EAS CLI не авторизован (`Not logged in`), а сборка требует вашего логина.
> Конкретное действие: выполнить `eas login` и `eas build --platform android --profile
> preview-seeded`, затем прислать агенту ссылку на сборку.

## 4. Как получить уведомление в день установки (тестовый fixture)

**Проблема.** Новый контакт имеет минимальный срок **2 календарных дня**
(`INITIAL_INTERVAL_DAYS`); фиксация взаимодействия только переносит срок вперёд. Поэтому
через обычный UI получить просрочку «сразу» **нельзя**, а без просроченного контакта
уведомление придёт только через 2 дня.

**Решение — сборка `preview-seeded`.** При её запуске приложение один раз создаёт
**тестовый контакт** «Тестовый контакт (просрочен)» с датой создания в прошлом (срок уже
прошёл). Это тестовые **данные**, подготовленные отдельно от продакшн-логики (модуль
`src/features/testSeed.ts`). Флаг `EXPO_PUBLIC_SEED_DUE_CONTACT=1` встраивается в
JS-бандл на этапе сборки профиля `preview-seeded` (статическое `process.env.*`) — в
самом приложении ничего включать не нужно.

Как получить уведомление:

1. Установите и запустите сборку **`preview-seeded`** — в списке появится контакт
   «Тестовый контакт (просрочен)» (он сразу в разделе «Пора связаться»).
2. Откройте настройки напоминаний и поставьте **время на 1–2 минуты позже** текущего
   времени телефона.
3. Включите «Напоминания» и разрешите уведомления.

Тогда anchor = сегодня, и реальное сводное уведомление придёт сегодня в это время
(возможна небольшая задержка доставки — это допустимо, решение Q1). Уведомление
**настоящее**: его планирует обычная продуктовая логика по реально просроченному
контакту. Моделируется только исходное состояние данных — событие показа не подменяется.

> **Важно.** Фикстура **не является** продуктовой функцией: она не меняет алгоритмы,
> интервалы и правила напоминаний, не добавляет ничего в UI и активна только в сборке
> `preview-seeded`. Тестовый контакт останется в базе после smoke-теста (удаление
> контактов — Stage 5); при желании очистите данные приложения: **Настройки Android →
> Приложения → Orbit → Хранилище → Очистить данные**, либо установите обычную сборку
> `preview`.

## 5. DEFERRED / NOT TESTED — платформенные проверки (принятый риск)

Эти проверки **не требуются** от владельца в рамках минимального smoke-теста и
фиксируются как **NOT TESTED** с указанием риска; успешно проверенными они **не**
объявляются и автотестами **не** подменяются.

| §12 | Проверка | Почему отложено | Риск |
|---|---|---|---|
| 15 | Реальная смена часового пояса | поведение ОС при закрытом приложении | уже поставленный момент не переписывается до следующего открытия |
| 16 | Перезагрузка устройства | требует перезагрузки/времени | запланированные уведомления могут не восстановиться на части OEM-прошивок |
| 18 | Многодневная автономность (реально) | требует дней ожидания | горизонт конечен (366 дней); при простое дольше — новые не планируются |
| 19 | Force-stop приложения | платформенное ограничение Android | после ручной остановки уведомления не приходят до перезапуска |
| — | Doze / троттлинг точности доставки | поведение ОС | время доставки неточное (exact-alarm не запрашиваем, Q1) |

## 6. Что прислать агенту после четырёх действий

1. Ссылку на сборку + версию Android и модель устройства.
2. Результат по каждому из 4 действий: **PASS / FAIL** (+ фактическое поведение для FAIL).
3. Скриншоты/описания для FAIL.

После этого агент занесёт **реальные** результаты в `REVIEW_REPORT.md` (отложенные
пункты — как NOT TESTED с риском), при FAIL подготовит минимальные исправления
отдельными коммитами (без изменения утверждённых алгоритмов) и остановится для
повторного независимого ревью. **Stage 4 не объявляется завершённым до вашего
окончательного утверждения.** Stage 5 не начинается.
