# Обмен файлами между ноутбуком и агентом (проект Orbit)

Агент работает в отдельной среде и не имеет доступа к ноутбуку. Обмен идёт через личный
AI Drive: две папки, у каждой своё направление. Пользователь делает свою часть двойным
щелчком по `orbit.cmd` и выбором пункта меню; агент делает свою часть командой `gsk`.

> **Основной канал передачи изменений — GitHub** (рабочие ветки и Pull Request'ы в
> репозитории проекта; см. `AGENTS.md`, `docs/DEVELOPMENT.md`). Описанный здесь обмен
> патчами через AI Drive — **резервный**: он нужен, если GitHub недоступен или владелец
> отдельно просит патч. В остальных случаях изменения идут коммитами в рабочую ветку и PR.

| Папка на AI Drive | Направление | Файлы |
|---|---|---|
| `/orbit_sync/from_laptop/` | ноутбук → агент | `orbit_from_laptop.zip`, `PUSH_INFO.txt` |
| `/orbit_sync/to_laptop/` | агент → ноутбук | `orbit_patch.zip`, `PATCH_INFO.txt` |

Обе стороны перезаписывают свои файлы на месте (в `gsk` это флаг `--override`), поэтому
в AI Drive не накапливаются версии и нет «дубликатов через скобки».

## Новый чат с агентом (передача контекста)

Песочница агента одноразовая: в новом чате у агента нет памяти о прошлом разговоре.
Контекст живёт в самом проекте, поэтому порядок такой:

1. На ноутбуке: VPN → `orbit.cmd` → пункт **2** (отправить срез агенту). Срез
   содержит рабочее дерево, историю git и `docs/PROJECT_STATE.md`.

   Пункт 2 нужен ТОЛЬКО когда: (а) начинается новый чат — песочница агента
   чистая, проект ей неоткуда взять кроме AI Drive; (б) на ноутбуке правились
   файлы локально — иначе следующий патч агента молча перезапишет эти правки;
   (в) песочница агента была пересоздана посреди чата. В рамках живого чата
   с неизменённым ноутбуком ничего отправлять не нужно — агент сам выкладывает
   каждый законченный этап патчем в `to_laptop`.
2. В новом чате отправить агенту шаблон (ниже) — одной репликой.
3. Агент скачивает архив из `/orbit_sync/from_laptop/`, сверяет sha256,
   распаковывает и читает `docs/PROJECT_STATE.md` ПЕРВЫМ файлом — там текущий
   stage, статус, следующий шаг и открытые вопросы.

Шаблон реплики для нового чата:

```text
Проект Orbit (Expo + TS, local-first), продолжаем по стейджам.
Срез проекта я отправил на AI Drive: /orbit_sync/from_laptop/orbit_from_laptop.zip
(+ PUSH_INFO.txt, сверь sha256). Скачай и распакуй.
Первым файлом прочти docs/PROJECT_STATE.md — там текущий stage, статус и следующий
шаг. Правила работы: AGENTS.md (ритуал завершения Stage, коммиты), обмен файлами:
docs/SYNC.md, доменные правила: docs/DOMAIN.md.
Действуй строго по зафиксированному следующему шагу, не выходи за рамки текущего
stage; закончишь — по ритуалу: проверки, REVIEW_REPORT.md, патч в /orbit_sync/to_laptop,
ожидание approval.
```

Что бы ни обсуждалось в чате, решения и факты фиксируются в файлах проекта
(`docs/PROJECT_STATE.md`, `docs/DOMAIN.md`, планы в `docs/plans/`) — только они
переходят в следующее окно.

## Аккаунты Genspark

У каждого аккаунта Genspark свой AI Drive, поэтому синхронизатор привязывает проект
к аккаунту, под которым выполнялась настройка (`init`/`setup`): email из `gsk me`
сохраняется в `account.txt` рядом со скриптом и показывается в меню и в `status`
(строки «Аккаунт Genspark» / «Проект привязан к…»). В `PUSH_INFO.txt` и
`PATCH_INFO.txt` добавляется поле `account:` — по нему обе стороны видят, через какой
аккаунт идёт обмен. Перед `push` и `pull` скрипт сверяет текущий вход с привязанным
и отказывает при несовпадении («Аккаунт не тот…») — иначе файлы ушли бы не в тот
AI Drive. Перепривязка под намеренно другой вход: пункт 7 меню или
`orbit-sync.ps1 account` / `orbit-sync.sh account`.

## Размещение синхронизатора

Папка с синхронизатором **может лежать и внутри проекта, и рядом с ним** — например
`D:\Pr\orbit_sync` при проекте `D:\Pr\orbit`. Пользователь указывает папку проекта
один раз (пункт 6 меню или `orbit-sync.ps1 project -ProjectDir <путь>`); путь сохраняется
в `project.txt` рядом со скриптом.

Порядок определения папки проекта: флаг `-ProjectDir` → `project.txt` → поиск вверх по дереву
от папки скрипта и от текущего каталога по признакам (`AGENTS.md`, `requirements.txt`,
`pytest.ini`, `pyproject.toml`, `setup.py`, `package.json`, `.git`).

Рабочий каталог `.sync` (загрузки, копии перезаписанных файлов, собранные архивы) всегда
лежит рядом со скриптами, а не в проекте — проект не засоряется.

## Как агент получает срез проекта

```bash
gsk aidrive download /orbit_sync/from_laptop/PUSH_INFO.txt ./PUSH_INFO.txt
gsk aidrive download /orbit_sync/from_laptop/orbit_from_laptop.zip ./orbit_from_laptop.zip
sha256sum orbit_from_laptop.zip     # сверить с archive_sha256 из PUSH_INFO.txt
unzip -q orbit_from_laptop.zip -d <папка>
```

Поля `PUSH_INFO.txt`: `created_utc`, `host`, `user`, `os`, `project_dir`, `branch`, `head`,
`uncommitted_files`, `archive`, `archive_bytes`, `archive_sha256`, `files_count`,
`git_dir_included`. Архив содержит рабочее дерево по правилам `.gitignore` плюс папку
`.git` (историю коммитов), если проект под git и не указан `-NoGit`.

## Как агент отдаёт изменения

```bash
bash tools/sync/make_patch.sh -d <корень проекта> -v 20261004-01 \
     -m "Что сделано на этом этапе" \
     app/... tests/... docs/PROJECT_STATE.md AGENTS.md
```

- версия — `ГГГГММДД-NN`, увеличивается при каждой выдаче;
- без списка файлов скрипт берёт все файлы под контролем git;
- файлы, которые нужно удалить у пользователя, перечисляются флагами `--deleted <путь>`;
- `--no-upload` — только собрать архив, не выкладывать;
- скрипт сам заливает `orbit_patch.zip` и `PATCH_INFO.txt` в `/orbit_sync/to_laptop`.

Поля `PATCH_INFO.txt`: `version`, `created_utc`, `created_by`, `message`, `base_head`,
`archive`, `archive_bytes`, `zip_sha256`, `files_count`, список `files:` с sha256 каждого
файла и, при необходимости, `deleted:`.

После выкладки агент пишет пользователю: «изменения готовы, нажмите 3».

## Как пользователь забирает изменения

Двойной щелчок по `orbit.cmd`, пункт **3**. Скрипт:

- скачивает описание, сравнивает версию с применённой ранее (`.sync/last_version.txt`);
- скачивает архив и сверяет `zip_sha256`;
- копирует перезаписываемые файлы в `.sync/backup/<версия>/`;
- распаковывает файлы в проект, удаляет перечисленные в `deleted`;
- повторный запуск на ту же версию ничего не делает (принудительно — флаг `-Force`).

## Пункты меню `orbit.cmd`

| Пункт | Что делает |
|---|---|
| 1 | первая настройка: проверка связи с Genspark, установка `gsk`, вход в аккаунт, папки в AI Drive, запоминание папки проекта |
| 2 | отправка среза проекта агенту |
| 3 | получение и применение патча агента |
| 4 | состояние: папка проекта, папка обмена, версия git, изменённые файлы, применённый патч, что ждёт на AI Drive |
| 5 | проверка доступа к Genspark (интернет и VPN) |
| 6 | указать (или сменить) папку проекта — сохраняется в `project.txt` |
| 0 | выход |

## VPN

Сеть пользователя отклоняет запросы к Genspark без VPN (проверено на прошлом проекте: ответ
«доступ запрещён»). Включённый VPN должен действовать на весь компьютер, а не только в
браузере. Поэтому перед каждым пунктом 2 и 3 пользователю нужно напоминать включить VPN;
пункт 5 показывает, работает ли доступ.

## Состав архива

В git-репозитории состав берётся из `git ls-files --cached --others --exclude-standard`,
то есть по правилам `.gitignore` проекта: `.env` и ключи, `.venv`, `*.sqlite3`, кэши
(`__pycache__`, `.pytest_cache`, `.pytest_tmp`), архивы остаются на ноутбуке.
Если проект не под git или git не найден, применяется тот же набор исключений, заданный
в скрипте. Каталог `.git` **скрыт на Windows** — в проводнике виден только при включённом
«Вид → Показать → Скрытые элементы»; в архив он попадает как история коммитов.

Изменения после применения патча пользователь коммитит сам; агент не выполняет `git commit`
и `git push` без его просьбы.

## Переводы строк

Файлы репозитория в индексе git хранятся с переводами строк LF, а рабочее дерево на
Windows — с CRLF. Поэтому в распакованном архиве `git status` показывает все файлы
изменёнными. Реальные изменения смотреть так:

```bash
git diff --ignore-cr-at-eol
```

Новые файлы создавать с LF, существующие не переписывать целиком только ради переводов строк.
