## Что сделано (вертикальный срез F1–F4)

    `daysBetween`: reference = дата последнего взаимодействия (`MAX(occurredAt)`)
    или `createdAt`; `nextDueDate = reference + recommendedIntervalDays`;
    `isDue = today >= nextDueDate`; сравнение по ЛОКАЛЬНЫМ календарным датам

- **UI/app** (по `DESIGN.md`, поправки 1–3 учтены): три экрана — список

## Исправления по внешнему ревью (REVIEW-01/02/03) — 2026-10-08

Ревью коммита `5deaf7d` — **CHANGES REQUESTED** (три замечания). Исправлено
без изменения утверждённой бизнес-логики (алгоритмы Stage 1, due-правила
Stage 3 и миграция SQLite v2 не тронуты); функциональность вне Stage 3 не
добавлялась; утверждённый дизайн не менялся; существующие тесты не ослаблялись.

- **REVIEW-01 (MEDIUM) — кнопка сохранения в шторке.**
  `src/ui/InteractionSheet.tsx`: кнопка «Сохранить» теперь **неактивна, пока не
  выбраны оба значения** — инициатор и результат (`disabled = saving ||
  incomplete`), в соответствии с `DESIGN.md` §8 («сохранение недоступно, пока
  выбран не каждый из двух») и §6.3. Ранее кнопка блокировалась только при
  `saving`. Пока форма неполна (или при ошибке сохранения с экрана) показывается
  сообщение «Выберите инициатора и результат.». Бизнес-логика не изменялась —
  выбор остаётся локальным состоянием представления.
- **REVIEW-02 (MEDIUM) — аппаратная кнопка «Назад» Android.**
  `src/app/contact/[id].tsx`: при открытой шторке регистрируется обработчик
  `BackHandler.addEventListener("hardwareBackPress", …)`, который первым нажатием
  закрывает шторку и поглощает событие (`return true`) — навигация со страницы
  контакта НЕ выполняется. При закрытой шторке обработчик не зарегистрирован,
  поэтому действует стандартный переход назад (`DESIGN.md` §7). Добавлен
  компонентный тест (`contactCardScreen.test.tsx`): при закрытой шторке перехват
  не регистрируется; при открытии — регистрируется; нажатие поглощается,
  закрывает шторку и НЕ вызывает `router.back`; повторное открытие снова
  регистрирует перехват. **Фактическое поведение на устройстве вынесено в
  чек-лист владельца** (раздел «Manual verification», пункт 10).
- **REVIEW-03 (LOW) — повторная инициализация после ошибки.**
  `src/features/runtime.ts`: отклонённый промис инициализации больше не остаётся
  в кеше — в `.catch` кеш сбрасывается, поэтому следующий вызов
  `getOrbitServices()` повторяет попытку; при успешном запуске инициализация
  по-прежнему единственная (общий промис для всех вызывающих). Добавлен
  unit-тест (`runtime.test.ts`): после ошибки следующий вызов повторяет попытку
  (БД открывается дважды); при успехе — ровно один раз и один и тот же промис.

## Решения технических уточнений §13 `DESIGN.md` (минимальные)

   `react-native-svg`; как в прототипе.
3. **Шрифты** — официальные пакеты `@expo-google-fonts/unbounded` +
   `@expo-google-fonts/manrope` через `expo-font` (уже в зависимостях).

5. **Авто-скрытие баннера** — 7 с (как в прототипе), с крестиком.
6. **Даты** — `Intl.DateTimeFormat('ru-RU')`: краткая «4 окт» (история),
   полная «8 октября 2026» (плитка).
7. **Оттенок `muted`** — оставлены утверждённые значения палитры; проверка
   контраста на устройстве — за ручной проверкой (фаза 6).
8. **«Срок не рассчитан» в плитке** — прочерк «—» вместо даты.
9. **Аппаратная «Назад» Android при открытой шторке** — перехватывается и
   закрывает шторку без навигации (REVIEW-02); при закрытой шторке — стандартный

не заменяет нативный `expo-sqlite`.

Подготовка: применить патч (`orbit.cmd`, пункт 3, VPN включён), затем в
`D:\Pr\orbit`: `npm install`, `npm run android` (устройство/эмулятор) или
`npx expo start` + Expo Go.

Чек-лист (план Stage 3):
1. Приложение запускается на Android; пустой список → «Пока никого нет».
2. Добавить контакт (имя + явный выбор стратегии) → контакт в списке, интервал = 2.
3. **Рост:** зафиксировать `no_reply` → интервал 2 → 4; повторить → 8.
4. **Сокращение (REVIEW-01):** на контакте `grow` с интервалом 4 (после `no_reply`)
   зафиксировать `them + good` → интервал 4 → 3.
5. **Нижняя граница:** при интервале 2 зафиксировать `them + good` → остаётся 2.
6. Полностью закрыть и перезапустить приложение → контакты, интервалы и история
   на месте (нативный `expo-sqlite` переживает перезапуск).
7. Главный экран: контакты с наступившим сроком — сверху, блок «Пора связаться».
8. Оценить удобство сценариев на телефоне (клавиатура, шторка, кольца).
9. **Шторка (REVIEW-01):** при открытой шторке «Зафиксировать общение» кнопка
   «Сохранить» неактивна, пока не выбраны и **и** инициатор, и результат; после
   выбора обоих — активна и сохраняет взаимодействие.
