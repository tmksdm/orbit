## 1. Общее визуальное направление

Направление **B «Ритм»** (описание из дизайн-handoff OpenDesign):

> «Компактный, карточки с визуализацией ритма: прогресс-кольцо и крупное число
> дней до контакта».

- **Светлая тема** (тёмная тема не утверждена — вне scope).
- **Фиолетовый акцент**; сигнальный цвет «пора связаться» — отдельный (розово-красный).
- **Карточки контактов** с прогресс-кольцом ритма.
- Компактная плотность, спокойная иерархия, минимум визуального шума.
- Без избыточных теней, скруглений и анимаций (одна мягкая тень у карточки —
  намеренная часть направления).

Базовый фон, поверхности, текст и линии — из палитры §2; шрифты — §3; сетка — §4.

**Семантика кольца (единая на всех экранах, см. §11 поправка 3):**
- число внутри кольца — **текущий рекомендуемый интервал в днях** (`recommendedIntervalDays`);
- дуга кольца — **прогресс времени** относительно рекомендуемого интервала
  (сколько прошло от опорной даты к интервалу);
- состояние наступившего срока обозначается единообразно сменой цвета дуги и
  заливки/обводки карточки (§5).

## 5. Компоненты и их состояния

**Карточка контакта (список).**
- Обычная: border `line`, фон `surface`, тень `shadow-card`.
- «Пора связаться»: border `due-line`, фон `due-bg`.
- Нажатие: Ripple/подсветка (материальный отклик) — точный оттенок требует
  уточнения (§13).

**Кольцо ритма.**
- Норма: дуга цветом `accent` поверх трека `line`, число `ink`.
- «Пора»: дуга цветом `due`.
- Прогресс `p` — процент заполненной дуги; в прототипе
  `p = clamp(round(elapsed / recommendedIntervalDays × 100), 6, 100)`.
  Нижний порог 6% — визуальный приём, чтобы дуга была видна нулевым значением;
  **требует подтверждения** (§13). Верх — 100% (наступивший и просроченный срок
  показывается полностью заполненной дугой в цвете `due`).

**Чип «Пора связаться»** (если используется вне карточек): padding `4px 9px`,
радиус 999px, фон `due-bg`, текст `due` 11/700, border 1px `due-line`.

**Чип стратегии** (карточка контакта): padding `3px 9px`, радиус 999px,
фон `accent-soft`, текст `accent` 11/700.

**Кнопки.**
- Primary: фон `accent`, текст `accent-ink`, min-height 48px.
- Secondary/базовая: фон `surface`, border `line`, текст `ink`.
- Disabled (`aria-disabled`): opacity .45, без реакции на нажатие.
- Нажатие/«pressed» на Android — материальный отклик (точный приём уточняется, §13).

**Поле ввода.**
- Обычное: border `line`, фон `surface`.
- Фокус: border `accent` + кольцо `0 0 0 3px accent-soft`.
- Ошибка: под полем текст-ошибка `err` (13/600, `due`), например
  «Укажите имя — без него контакт не сохранить.».
- Placeholder: `muted` (opacity .8).

**Карточка стратегии (выбор ровно одного).**
- Обычная: border `line`, фон `surface`, индикатор — рамка 2px `line`.
- Выбранная: border `accent`, внутренняя обводка `inset 0 0 0 1px accent`,
  фон `accent-soft`, индикатор — заливка `inset 0 0 0 4px accent` (одиночный
  индикатор-«радио»). Нажатие — на всю карточку (см. §11 поправка 1).
- Выбор по умолчанию отсутствует.

**Баннер** (обратная связь после сохранения): фон `accent-soft`, border `accent`;
заголовок 13/700, строки 13/400 `muted`; закрытие крестиком; авто-скрытие —
в прототипе 7 с (подтвердить, §13).

**Скелетон загрузки:** 5 строк-заглушек (аватар 44×44 + две линии), заливка
`line`, анимация «пульс» 1.2 с (вкл/выкл — §13; при reduced-motion отключена).

## 6. Экраны

Порядок и содержание соответствуют утверждённым сценариям F1–F3 плана Stage 3.
Тексты — русские (прототип B).

### 6.1. Главный экран — список контактов

- **Шапка:** заголовок «Orbit», подзаголовок — «N контактов [· M пора связаться]»
  (для не-данных: «Локально на устройстве»).
- **Секция «Пора связаться»** (если есть): заголовок + счётчик (цвет `due`);
  ниже — карточки контактов с наступившим сроком.
- **Секция «Остальные»:** карточки остальных контактов.
- **Карточка:** кольцо (число = интервал, дуга = прогресс) + имя + заметка
  (одна строка, ellipsis) + мета «раз в N дней · <когда>».
  - «когда» для due: «просрочено на N дней» / «пора связаться сегодня»;
  - иначе: «через N дней» / «сегодня».
- **Футер:** primary-кнопка «Добавить человека».
- **Порядок:** due-контакты сверху (по возрастанию `nextDueDate`), затем
  остальные (см. бизнес-правило порядка — §12, план Stage 3).

### 6.2. Добавление контакта

- **Шапка:** «Назад» + заголовок «Новый контакт» + подзаголовок «Добавление
  контакта».
- **Поля:**
  - **Имя** — обязательно; пометка «обязательно» (красный текст); placeholder
    «Например, Марина Соколова».
  - **Заметка** — пометка «необязательно» (серый текст, **без плашки**);
    textarea, placeholder «О чём стоит помнить при общении».
  - **Стратегия связи** — обязательно; legend + пометка «обязательно»;
    пояснение: «Стратегия задаёт ритм общения. Выбор нельзя пропустить —
    автоматического значения нет.»; две карточки-опции:
    - «Не потерять связь» — «Спокойный ритм, чтобы не быть навязчивым. Интервал
      может постепенно расти и никогда не сокращается ради сближения.»
    - «Сближаться» — «Постепенное сближение, но только по взаимности: интервал
      сокращается лишь тогда, когда инициатива идёт от другого человека и
      общение прошло хорошо.»
- **Футер:** primary-кнопка «Сохранить»; при невалидной форме — неактивна
  (opacity .45) + подсказка «Укажите имя и выберите стратегию».
- **Валидация:** имя пустое → ошибка под полем; стратегия не выбрана → ошибка
  «Выберите одну из стратегий.».

### 6.3. Карточка контакта

- **Шапка:** **только «Назад»** — без имени контакта (см. §11 поправка 2).
- **Верхний блок:** кольцо + имя (крупно) + чип стратегии.
- **Блок «Пора связаться»** (если срок наступил): «Пора связаться · просрочено
  на N дней», фон `due-bg`.
- **Заметка** (если есть).
- **Показатели (2 плитки)** — см. §11 поправка 3:
  - «следующий контакт» — дата;
  - «взаимодействий» — количество.
- **История взаимодействий** — заголовок «История»; строки (дата, инициатор,
  результат); пустое состояние: «Взаимодействий пока нет. Отсчёт идёт от даты
  добавления контакта.».
- **Футер:** primary-кнопка «Зафиксировать общение» → нижняя шторка:
  - «Кто был инициатором»: «Вы» / «Другой человек» / «Взаимно»;
  - «Как прошло»: «Хорошее общение» / «Короткое общение» / «Нет ответа»;
  - ошибка при неполном выборе: «Выберите инициатора и результат.»;
  - кнопка «Сохранить».

## 7. Навигация

- **Список → Карточка:** нажатие на карточку контакта.
- **Карточка → Список:** кнопка «Назад».
- **Список → Добавление:** кнопка «Добавить человека» (футер) или из пустого
  состояния.
- **Добавление → Список:** «Назад» (без сохранения) или «Сохранить» (после
  валидного сохранения — возврат в список).
- **Карточка → Шторка «Зафиксировать общение»:** кнопка в футере; закрытие —
  тап по затемнению.
- Переходы — стандартные для Android (back-жест/кнопка «Назад» работает как
  «Назад»). Тип перехода (push/слайд) — стандартный стек; кастомные анимации не
  вводятся.

## 8. Поведение элементов управления

- **Карточка контакта** — вся область кликабельна (переход в карточку).
- **Карточка стратегии** — кликабельна целиком; выбирается ровно одна;
  выбранная визуально отличается (одиночный индикатор + заливка + обводка);
  значение по умолчанию не выбрано.
- **Кнопка «Сохранить» (добавление)** — неактивна, пока не заданы имя и
  стратегия; подсказка под кнопкой.
- **Шторка** — выбор инициатора и результата обязателен для сохранения;
  сохранение недоступно, пока выбран не каждый из двух.
- **Баннер** — появляется после сохранения; закрывается крестиком; авто-скрытие
  по таймеру (см. §13).
- **Скролл** — только в теле экрана; шапка и футер закреплены.

## 9. Состояния экрана (пусто / загрузка / ошибка)

- **Данные** — обычный список (§6.1).
- **Загрузка** — скелетон из 5 строк (§5), помечен как «загружается».
- **Пусто** — иконка (человек+), заголовок «Пока никого нет», текст «Добавьте
  первого человека — и Orbit подскажет, когда стоит напомнить о себе.»,
  кнопка primary «Добавить человека».
- **Ошибка** — иконка-предупреждение, заголовок «Не удалось показать контакты»,
  текст «Данные хранятся только на устройстве. Попробуйте ещё раз.», кнопка
  «Повторить».
- Состояния загрузки/ошибки/пустоты списка **не** показывают футер с кнопкой
  «Добавить человека» (в прототипе футер есть только в состоянии «Данные»);
  при этом пустое состояние содержит свою кнопку «Добавить человека».

## 10. Адаптация к Android

- **Ориентация:** портретная (основной сценарий).
- **Системные области (safe areas):** в прототипе верхний/нижний системные
  отступы заданы константами оболочки (52px / 28px) — это значения *демо-рамки*,
  а не спецификация приложения. В приложении использовать **реальные инсеты
  устройства**: верхний — под строку состояния, нижний — под систему навигации
  (жестовую панель). Конкретный способ (например, `react-native-safe-area-context`)
  — решение этапа реализации; на текущем шаге зависимости не добавляются.
- **Строка состояния:** системная; **не рисовать** собственную строку состояния
  и индикатор жеста (в прототипе это оформление рамки).
- **Клавиатура:** форма добавления и футер должны оставаться доступными при
  открытой экранной клавиатуре — удерживать фокус и кнопку «Сохранить» над
  клавиатурой (материальный паттерн KeyboardAvoidingView / поведение Android).
  Конкретный приём — на этапе реализации.
- **Зона нажатия:** ≥44dp (см. §4).
- **Шрифты:** подключение Unbounded и Manrope в React Native (сборка/загрузка
  шрифтов) — решение этапа реализации; на текущем шаге зависимости не
  добавляются.
- **Тёмная тема:** не утверждена; вне scope.

## 11. Три утверждённые поправки владельца (2026-10-08)

### Поправка 1. Экран добавления

- **Убрать** отдельную белую плашку вокруг слова «необязательно» рядом с полем
  «Заметка».
- Пометки **единообразны**: «обязательно» — обычный красный текст (`due`);
  «необязательно» — обычный серый текст (`muted`). Без фона, границ и паддингов.
- Выбор стратегии визуально означает выбор **ровно одного** варианта: использовать
  радиокнопку или эквивалентный одиночный индикатор, **сохранив** нажатие на всю
  карточку стратегии.
- **Стратегия по умолчанию не выбирается.**

### Поправка 2. Карточка контакта — заголовок

- Убрать повторение имени контакта в верхней шапке.
- В верхней части — **только навигация назад**.
- Основное имя контакта показывать **рядом с круговым индикатором**.

### Поправка 3. Карточка контакта — показатели

- Убрать отдельную плитку «N дней интервал» (интервал уже показан числом в круге).
- Оставить **две** плитки: «следующий контакт» и «взаимодействий».
- Кольцо имеет **одинаковую семантику** на главном экране и в карточке:
  число внутри — текущий рекомендуемый интервал в днях; дуга — прогресс времени
  относительно интервала; состояние наступившего срока обозначается единообразно.
- **Число внутри кольца не меняется между экранами** (одно и то же значение).

## 12. Разделение визуальных решений и бизнес-логики

**Этот документ (визуальное):** цвета, типографика, размеры, отступы, компоненты
и их состояния, разметка трёх экранов, навигация, адаптация к Android.

**НЕ этот документ (бизнес-логика — определяется документами Orbit):**
`docs/DOMAIN.md`, `docs/PRODUCT.md`, `docs/plans/stage-3-ui.md`. Ключевое, что
интерфейс только **отображает**, но не задаёт:

- стартовый интервал нового контакта — **2 дня**; минимальный — **2 дня**;
  верхней границы нет;
- `no_reply` — **×2.0 накопительно**; утверждённые множители стратегий;
- правило «пора связаться»: `today >= nextDueDate`,
  `nextDueDate = referenceDate + recommendedIntervalDays`, где reference —
  **последнее взаимодействие**, а при его отсутствии — `createdAt`;
- старые контакты с `createdAt = NULL` и без истории — срок не рассчитывается;
- обязательный **явный** выбор стратегии; редактирование/удаление — вне scope;
  уведомления/авторизация/AI — вне scope.

**Прототип OpenDesign — визуальный ориентир, а не источник бизнес-логики.**
Демонстрационная логика прототипа (например, стартовые интервалы 14/30 дней и
изменение интервала «+7/−7 дней» внутри его скрипта) **НЕ переносится** в
production-код. Источник истины — утверждённые документы Orbit.

**Отображение данных из domain:** число в кольце — `recommendedIntervalDays`;
прогресс дуги — по опорной дате (последнее взаимодействие или `createdAt`) и
интервалу; состояние «пора» — по due-функции domain. UI не вычисляет
бизнес-правила самостоятельно (`ARCHITECTURE.md`).

## 13. Требует уточнения (не определено однозначно в исходных материалах)

Ни одно из нижеследующего не выдумывается; помечается как решение/уточнение:

1. **Состояние нажатия (pressed)** для карточек, кнопок и опций — в прототипе
   есть только `hover` (неактуален на Android); нужен материальный отклик
   (ripple/подсветка) — конкретный приём и оттенок.
2. **Иконки** (пустое состояние — «человек+», ошибка — предупреждение, «Назад» —
   шеврон): в прототипе это inline-SVG; выбрать источник иконок в React Native.
3. **Подключение шрифтов** Unbounded/Manrope в приложении — способ загрузки
   (зависимости на текущем шаге не добавляются).
4. **Нижний порог дуги кольца (6%)** — подтвердить, что при малом прогрессе дуга
   остаётся заметной; иначе задать иное min-значение.
5. **Авто-скрытие баннера** (в прототипе 7 с) — подтвердить или задать иное.
6. **Форматирование дат** — в прототипе `ru-RU` (краткая и полная формы);
   подтвердить как стандарт отображения.
7. **Точный оттенок `muted`** — проверить контраст по WCAG AA для второстепенного
   текста на `bg`/`surface` и при необходимости скорректировать.

Не вводить тёмную тему, звуки, кастомные анимации и прочие элементы вне
утверждённого объёма.
